# api/rate-limiting Specification

## Purpose
Техническое поведение backend: ограничение частоты запросов к публичному API. Бизнес-поведения не описывает, живёт только в репозитории backend.

## Requirements

### Requirement: Ограничение неудачных попыток
API SHALL ограничивать число неудачных попыток для эндпоинтов, подверженных перебору, и отвечать `429` с заголовком `Retry-After`.

#### Scenario: Превышен лимит неудачных попыток
- **WHEN** покупатель сделал 10 неудачных попыток за минуту
- **THEN** следующий запрос получает `429` и `Retry-After` в секундах
