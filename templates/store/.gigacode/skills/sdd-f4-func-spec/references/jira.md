# Jira: операции F4

Все вызовы идут через Jira MCP-сервер. Имена инструментов зависят от сервера; ниже перечислены операции, которые нужны skill. Подходящий инструмент выбирать по смыслу: поиск по JQL, чтение задачи, изменение полей.

## Поиск

JQL строит `python3 <skill>/scripts/f4.py jql` из `spaces.yml`. Пример результата:

```text
project in ("EVPF", "MKB", "ATRK") AND issuetype in ("Улучшение", "Improvement")
AND labels = "автофлоу" AND status = "Анализ"
AND "Текущий статус (краткий комментарий)" ~ "\"создана бизнес-спецификация\""
ORDER BY key ASC
```

- Если `status_field_kind: text`, JQL ищет текстовое поле через `~`, это полнотекстовый поиск. После поиска точное совпадение значения проверить самостоятельно.
- Если `status_field_kind: select`, используется `=`, и дополнительная проверка не нужна.
- Если поиск возвращает ошибку о поле, вместо имени поля можно подставить `cf[<число из status_field_id>]`.
- Читать все страницы результата, пока задачи не закончатся.

## Чтение задачи

Нужны поля: `summary`, `description`, `issuetype`, `status`, `labels`, `issuelinks`, `<status_field_id>`, а также `attachment` — чтобы перечислить вложения в источниках.

Связанная Story ищется в `issuelinks`: у каждой связи есть `inwardIssue` или `outwardIssue`, у них — `fields.issuetype.name`. Подходят `Story` и `История`. Направление и тип связи значения не имеют.

## Изменение поля статуса (шаг 9)

Меняется только поле `status_field_id`, workflow-переход не выполняется.

- `status_field_kind: text`:

  ```json
  {"fields": {"customfield_XXXXX": "создана функциональная спецификация"}}
  ```

- `status_field_kind: select`:

  ```json
  {"fields": {"customfield_XXXXX": {"value": "создана функциональная спецификация"}}}
  ```

После записи перечитать задачу и сравнить значение. Если MCP-сервер не умеет менять кастомные поля — не обходить это, а сообщить пользователю ключ задачи и значение, которое нужно поставить.
